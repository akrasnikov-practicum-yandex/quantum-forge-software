# Легковес

## Суть паттерна

Легковес — это структурный паттерн проектирования, который позволяет вместить большее количество объектов в отведённую оперативную память. Паттерн экономит память, разделяя общее состояние объектов между собой, вместо хранения одинаковых данных в каждом объекте.

## Проблема

Разработчик создаёт игру, где игроки перемещаются по карте и стреляют друг в друга с реалистичной системой частиц. Пули, снаряды и осколки красиво летают на экране.

На мощном компьютере разработчика всё работает отлично, но друг сообщает о тормозах и крахах программы через несколько минут запуска. Анализ логов показывает: игра падает из-за нехватки оперативной памяти.

Причина проста: каждая частица представлена собственным объектом с множеством данных. Когда на экране достигается пик интенсивности боя, новые объекты частиц не помещаются в доступную память, и приложение крашится.

## Решение

При анализе класса частиц становится видно, что цвет и спрайт занимают наибольший объём памяти и при этом хранятся в каждом объекте, хотя их значения одинаковы для большинства частиц.

Остальное состояние — координаты, вектор движения, скорость — отличаются для всех частиц. Эти поля можно рассматривать как контекст использования частицы.

**Разделение состояния:**
- **Внутреннее состояние** (неизменяемые данные): цвет, спрайт.
- **Внешнее состояние** (контекст): координаты, вектор движения, скорость.

Паттерн предлагает не хранить внешнее состояние в классе, а передавать его методам через параметры. Это позволяет повторно использовать одни и те же объекты в разных контекстах. Главное преимущество: потребуется гораздо меньше объектов, так как они будут отличаться только внутренним состоянием, а вариаций этого состояния не так много.

В примере с частицами достаточно трёх объектов с разными спрайтами и цветами — для пуль, снарядов и осколков. Такие облегчённые объекты называют легковесами.

**Хранилище внешнего состояния.** Внешнее состояние перемещается в контейнер, который управлял объектами до применения паттерна (в примере — главный объект игры). К его классу добавляют массивы для координат, векторов и скоростей частиц, плюс массив ссылок на объекты-легковесы.

Более элегантный подход — создать дополнительный класс-контекст, связывающий внешнее состояние с легковесом. Это позволяет использовать только один массив в контейнере.

Хотя контекстов будет столько же, сколько было исходных объектов, контексты занимают намного меньше места, так как самые тяжелые поля остаются в легковесах, а контексты просто на них ссылаются.

**Неизменяемость легковесов.** Объекты легковесов должны быть неизменяемыми, так как будут использованы в разных контекстах. Внутреннее состояние легковес получает через параметры конструктора. Он не должен иметь сеттеров и публичных полей.

**Фабрика легковесов.** Для удобства работы создаётся фабричный метод, принимающий внутреннее состояние желаемого объекта. Фабрика ищет уже созданные легковесы с таким же состоянием и повторно их использует. Если нужный легковес не найден, создаётся новый.

## Структура

1. Легковес применяется в программах с громадным количеством одинаковых объектов. Паттерн разделяет данные на легковесы и контексты.

2. **Легковес**: Содержит состояние, повторяющееся во множестве первоначальных объектов. Один легковес используется со множеством контекстов. Состояние здесь называется внутренним, состояние от контекста — внешним.

3. **Контекст**: Содержит уникальную для каждого объекта «внешнюю» часть состояния. Связан с одним из объектов-легковесов, хранящих оставшееся состояние.

4. **Поведение**: Чаще всего оставляется в Легковесе, с передачей значений контекста через параметры методов. Альтернативно, поведение можно поместить в контекст, используя легковес как объект данных.

5. **Клиент**: Вычисляет или хранит контекст (внешнее состояние легковесов). Для клиента легковесы выглядят как настраиваемые объекты, которые конфигурируются передачей контекста через параметры.

6. **Фабрика легковесов**: Управляет созданием и повторным использованием легковесов. Получает запросы с желаемым состоянием легковеса. Если легковес с таким состоянием существует, возвращает его; если нет — создаёт новый.

## Псевдокод

Пример демонстрирует, как Легковес экономит память при отрисовке миллионов объектов-деревьев на экране.

Паттерн выделяет повторяющуюся часть состояния из класса `Tree` (текстура, цвет, имя) в отдельный класс `TreeType`. Вместо хранения этих данных в каждом дереве, отдельные деревья ссылаются на несколько общих объектов.

Клиент работает с деревьями через фабрику, которая скрывает сложность кэширования общих данных. Результат: программа использует намного меньше памяти, позволяя отрисовать больше деревьев на одном и том же оборудовании.

## Применимость

Применяйте Легковес, когда выполнены все перечисленные условия:

- **В приложении используется большое число объектов.** Паттерн эффективен только при наличии тысяч или миллионов экземпляров.
- **Из-за этого высоки расходы оперативной памяти.** Количество объектов настолько велико, что их хранение превышает доступные ресурсы.
- **Большую часть состояния объектов можно вынести за пределы их классов.** Состояние можно разделить на внутреннее (общее) и внешнее (уникальное).
- **Большие группы объектов можно заменить относительно небольшим количеством разделяемых объектов.** Благодаря вынесению внешнего состояния, множество объектов можно сократить до небольшого набора легковесов.

## Шаги реализации

1. **Разделите поля класса на две части**: внутреннее состояние (значения одинаковы для большого числа объектов) и внешнее состояние/контекст (значения уникальны для каждого объекта).

2. **Сохраните внутреннее состояние в классе.** Убедитесь, что значения этих полей неизменяемы. Инициализируйте их только через конструктор.

3. **Превратите внешнее состояние в параметры.** Измените методы так, чтобы они получали внешнее состояние через параметры. Удалите эти поля из класса.

4. **Создайте фабрику.** Она должна кэшировать и повторно отдавать уже созданные объекты. Клиент должен запрашивать легковесы из фабрики с определённым внутренним состоянием, а не создавать их напрямую.

5. **Клиент должен хранить или вычислять контекст.** Вычисляйте или сохраняйте значения внешнего состояния и передавайте их в методы объекта легковеса.

## Преимущества и недостатки

**Преимущества:**
- Экономит оперативную память: разделение состояния позволяет вместить значительно больше объектов в доступную память.

**Недостатки:**
- Расходует процессорное время: поиск или вычисление контекста требует дополнительных вычислительных ресурсов.
- Усложняет код: введение множества дополнительных классов (легковесы, контексты, фабрики) делает архитектуру более сложной.

## Отношения с другими паттернами

- **Компоновщик и Легковес**: Часто совмещаются для реализации общих ветвей дерева с экономией памяти.
- **Легковес и Фасад**: Легковес показывает, как создавать много мелких объектов; Фасад показывает, как создать один объект, отображающий целую подсистему.
- **Легковес и Одиночка**: Могут напоминать друг друга, когда количество объектов сводится к одному. Однако есть два кардинальных отличия: Легковес позволяет иметь множество объектов, Одиночка ограничивает количество одним; легковесы должны быть неизменяемыми, а Одиночка допускает изменение своего состояния.
