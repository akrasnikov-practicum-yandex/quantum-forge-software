# Задание 2. Подготовка базы знаний

**Проект:** RAG-бот для корпоративной базы знаний QuantumForge Software
**Дата:** 2026-06-17

---

## Цель

Создать базу знаний, которого LLM **не видела** при обучении, чтобы честно проверить: бот отвечает
по векторному индексу (RAG), а не по «памяти» модели. Для этого взята известная модели
вселенная, а все ключевые термины заменены на вымышленные. Так получается аналог закрытой
корпоративной базы — модель не знает о ней ничего, кроме того, что мы загрузили.

## Какую вселенную взяли и почему

Исходная вселенная — **Star Wars**. Она хорошо известна любой современной LLM, поэтому без
анонимизации модель отвечала бы по памяти, и проверка RAG потеряла бы смысл. После сплошной
замены терминов мир превращается в самостоятельную вымышленную вселенную — назовём её
**«Astral Strife»** (замена для «Star Wars»), — внешне не узнаваемую как Star Wars, но
сохраняющую внутреннюю логику и связи.

Исходные тексты **сгенерированы**, а не скачаны со сторонних сайтов: это даёт гарантированно
чистый текст (без HTML), полный контроль над словарным запасом (каждый специфичный термин
попадает в словарь замен) и отсутствие проблем с сетью и лицензиями.

## Как устроена замена

Замена выполняется детерминированным скриптом
[`scripts/build_knowledge_base.py`](../scripts/build_knowledge_base.py) на основе словаря
[`terms_map.json`](../terms_map.json) (132 записи). Ключевые принципы:

1. **Longest-match-first.** Ключи словаря сортируются по убыванию длины, чтобы составной
   термин («Darth Vader») срабатывал раньше своей части («Vader»), а полные формы фракций
   («Galactic Empire») — раньше коротких («Empire»).
2. **Один проход.** Все ключи собираются в одну regex-альтернативу со `\b`-границами и
   `re.IGNORECASE`; замена идёт за один `re.sub` с callback. Один проход исключает каскадную
   повторную замену уже подставленных слов.
3. **Сохранение регистра.** Если оригинал был в нижнем регистре («clone» → «vat-born»),
   replacement тоже приводится к нижнему; для имён собственных берётся каноническое написание.
4. **Нормализация артиклей.** После замены меняется начальный звук слова
   («a lightsaber» → «a arc-glaive»), поэтому неопределённый артикль `a/an` пересчитывается
   по первой букве следующего слова («an arc-glaive»). Это сохраняет читаемость.
5. **Анонимизация имён файлов.** Имя выходного файла берётся из уже переименованного
   заголовка: `darth-vader.md` → `xarn-velgor.md`. Так в базе не остаётся «улик» даже в путях.
6. **Самопроверка.** После сборки `knowledge_base/` сканируется по всем ключам словаря;
   наличие любого оригинального термина — ошибка покрытия (скрипт вернёт ненулевой код).

### Что заменяется (категории словаря)

- **Персонажи:** `Darth Vader → Xarn Velgor`, `Luke Skywalker → Joran Skyrend`,
  `Yoda → Voda`, `Palpatine → Malkor`, и короткие формы (`Vader → Velgor`, `Skywalker → Skyrend`).
- **Фракции/организации:** `Jedi Order → Veyari Conclave`, `Sith → Drakkar`,
  `Galactic Empire → Helion Dominion`, `Rebel Alliance → Ember Coalition`,
  `Galactic Republic → Aurelian Concord`.
- **Технологии/корабли/оружие:** `lightsaber → arc-glaive`, `Death Star → Void Core`,
  `hyperdrive → fold-drive`, `blaster → pulse-caster`, `X-wing → Kestrel-X`,
  `TIE fighter → Sable fighter`, `droid → mechiton`.
- **Концепции/события:** `the Force → the Synth Flux`, `Clone Wars → Vat Wars`,
  `Order 66 → Directive Null`, `kyber crystal → reson crystal`.
- **Планеты:** `Tatooine → Dunhollow`, `Coruscant → Centra Prime`, `Hoth → Glaciax` и т.д.
- **Расы:** `Wookiee → Grellan`, `Jawa → Skret`, `Ewok → Tibbin`, `Hutt → Vossk`
  (с формами множественного числа).

Замены **курируемые и связные** (не случайный `faker`), чтобы мир остался логичным и
читаемым. `faker`/`uuid4`/`slugify` — допустимая альтернатива для генерации имён, но даёт
менее связный результат.

## Как запустить

```bash
cd quantum-forge-software
python scripts/build_knowledge_base.py
```

Скрипт читает `data/source_sw/*.md`, применяет замену и пишет результат в `knowledge_base/*.md`,
затем выполняет самопроверку.

## Результат и верификация

- **`knowledge_base/`** — 36 анонимизированных документов `.md` (один файл — одна сущность):
  10 персонажей, 7 планет, 6 технологий/кораблей, 5 фракций, 4 расы, 4 концепции/события.
- **`terms_map.json`** — словарь замен (132 записи: оригинал → вымышленное).
- **`scripts/build_knowledge_base.py`** — скрипт замены и сборки.
- **`data/source_sw/`** — исходные (до замены) статьи; вход скрипта, оставлены для
  воспроизводимости.

Проверки:
1. Скрипт сообщает **0 остаточных** оригинальных терминов из словаря по всему корпусу.
2. Независимый поиск по ~80 характерным словам Star Wars (Jedi, Sith, Force, Skywalker,
   lightsaber, Wookiee, Empire, …) по `knowledge_base/` — **0 совпадений**.
3. Ручная вычитка: тексты читаемы и логичны, мир воспринимается как самостоятельный и
   **не распознаётся** как Star Wars; имена файлов также анонимизированы.

## Известные ограничения

- Подмена терминов — поверхностная (лексическая). Стилистически тексты остаются связными,
  но очень характерные сюжетные конструкции теоретически могут косвенно намекать на источник;
  для целей задания (проверка RAG) это несущественно, т.к. все имена/названия уникальны.
- Эвристика артиклей не покрывает редкие случаи (silent «h», «u» как «you»); в сгенерированном
  корпусе такие сочетания не встречаются.
